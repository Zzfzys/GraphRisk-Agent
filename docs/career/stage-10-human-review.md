## 这一步为什么需要你

自动校验能判断格式、来源和某些事实是否一致；它不能替你回答“这份报告对我有帮助吗”“我能不能讲清这些实现”。因此代理只准备材料、核对事实与记录格式，不填写你的评价，不代签已读或熟练。十案是既有观察题集，先读再展开自动结果也不是盲测；本人意见不作为欺诈真值。

本次选择Stage10路线2冻结的10笔**首次、不同交易**，包含6个原成功和4个被拦截失败，不收入两次重复，不新生成，不按结果挑题。四个失败案没有已发布报告，原模型字段只供分析错误/使用障碍，不能作为通过校验的调查结论。自动6/10 Fail仍保持。

## 每案按四步看

先看F1～F5工具事实，再看原模型字段/报告，然后看政策出处/原文与未测量前提，最后写本人意见。每案建议5～10分钟，分两次各五案也可以；以实际用时记录，不把建议当已耗时。

| 编号 | 怎么读 |
|---|---|
| F1 | 交易金额/产品代码/相对事件秒；人工日历锚不等于真实交易日期 |
| F2 | 1h/24h/7d严格较早的历史计数/金额统计；不能推成10分钟卡尝试或独立认证账户数 |
| F3 | XGBoost主分数与模型版本，calibrated=false；不是已知欺诈概率 |
| F4 | 共享实体关系与返回/总匹配/截断情况；共享邮箱域不证明同一人或团伙 |
| F5 | 实验性图分数、邻居与relation_only；没有独立邻居分数不能填0，不参与主评分 |
| P1等 | 本案检索到的模拟政策块、版本/出处/封存原文；引用存在仍不证明触发前提 |

例如F2存在历史计数，而模型字段history_activity写none，就应指出两者不一致；不要只抄机器给出的错误名。对于缺图、无报告、未知条件，可以“不通过”“无法判断”或“不适用”并解释。成功报告的事实文字主要来自程序，不能因为句子通顺就说LLM理解了全部业务。

## 逐案记录要求

每案记录是否本人已读、日期/时间、事实一致性、引用与政策前提、未知/建议边界、实际辅助价值，并至少写一个F/P具体依据与自己的解释。四个维度可选pass、fail、uncertain、not_applicable；pending表示尚未填写。所有十案保留，不能只统计六个成功案或丢掉不适用项。

HTML仅在本地暂存你输入的意见。每做几案点“生成导出JSON”，选中后复制到文本编辑器，**另存E盘新文件**；没有自动下载，避免默认写到C盘。换浏览器/路径/端口可能无法读到原暂存，最终导出是可移交记录。复制Markdown模板另存后逐案填写同样有效，不强制你同时填两种格式。

JSON检查只确认来源绑定与填齐：每案已读、带时区日期、四个非pending判断、至少一项本案F/P引用及不少于10字的具体说明；另有本人昵称/自报确认。允许不通过和无法判断，检查不把它们改成成功，也不能认证身份或证明已经认真阅读。代理收到实际记录后仍需核对内容和疑问。
