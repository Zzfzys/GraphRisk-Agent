## 1. 学习方式

本阶段不安排一套与项目脱节的完整图学习课程。每条学习路线只补当前实现所需的最小知识，然后立刻通过 fixture、代码、指标或工具输出验证理解。

每条路线遵守以下循环：

```text
先写出自己当前的判断
  → 阅读指定项目代码和概念
  → 手算或运行一个最小实验
  → 对照实际输出修正判断
  → 用 3～5 句话解释给面试官听
```

每天学习 30～60 分钟即可。学习笔记建议放在个人笔记中；会影响项目语义、配置、实验或验收的结论必须同步写入 Stage 04 文档。不要复制大段定义，重点记录“这个概念如何约束当前代码”。

## 2. 学习完成后的能力

完成 Stage 04 后，应当能够独立回答：

1. GraphSAGE 如何为未在训练图中出现的新交易生成表示？

## 4. L0：环境、张量设备与可复现性（30 分钟）

### 要掌握的最小知识

- PyTorch 张量、模型参数和输入必须位于兼容设备；
- CUDA 可用性与项目正确性是两件事，CPU 回退必须能工作；
- PyTorch/PyG 版本、随机种子和确定性设置影响复现实验；
- “相同种子”不保证跨设备逐位相同，因此报告需要说明容差和实际设备；
- 锁文件保证依赖解析一致，但模型产物仍需记录配置、输入和内容哈希。

### 对照项目阅读

- `pyproject.toml` 与 `uv.lock`：依赖如何被冻结；
- `configs/train_baseline_ieee_cis.yaml`：Stage 02 如何记录训练配置；
- `src/graphrisk/training/train_baselines.py`：随机种子、metadata 和 artifact 的现有做法。

## 5. L1：图 schema、GraphSAGE 直觉与时间泄漏（45 分钟）

### 要掌握的最小知识

- 节点表示对象，边表示关系；同一个实体值应映射到稳定节点；
- 本项目是多类型实体图，但首版可以通过统一特征空间和节点类型编码运行一个受控 GraphSAGE 基线；
- GraphSAGE 的核心是聚合邻居信息，再与自身表示组合；
- 归纳学习允许根据节点特征和邻居生成新节点表示，不要求每个交易 ID 都在训练时出现；
- 时间泄漏不仅来自标签和特征，也可能来自未来才出现的边、节点度数和采样集合。

可用下面的简化式理解一层 GraphSAGE：

```text
neighbor_summary(v) = mean({h_u | u 是 v 的允许邻居})
h_v_new = activation(W_self * h_v + W_neighbor * neighbor_summary(v))
```

公式中的“允许邻居”必须满足目标交易的时间截止，而不是从全量静态图中随意取邻居。

### 对照项目阅读

- `docs/data/data-dictionary.md`：五类实体字段的真实含义和限制；
- `src/graphrisk/features/transaction_features.py`：严格历史窗口如何排除当前与同时事件；
- `src/graphrisk/investigation/relation_tools.py`：Stage 03 如何实现严格历史共享实体；
- `docs/plans/stage-03-implementation-roadmap.md` 的路线 4：直接关系证据与图风险证据的边界。

### 动手任务

手绘 5 笔交易，至少包含：

- 两笔早晚交易共享 card；
- 两笔同时间交易共享 device；
- 一笔未来交易共享 email；
- 两个 `unknown-*` 占位 address。

以中间一笔为目标，用两种颜色标出允许边和禁止边。然后回答：如果先构建全量静态图再训练，目标的节点度数或两跳邻居会泄露什么？

### 自测问题

- 为什么同时间共享 device 不能称为“历史行为”？
- 为什么交易投影图可能因高频邮箱域产生 clique 爆炸？
- 为什么历史邻居的 `is_fraud` 也不应直接进入首版节点特征？
- 新设备没有历史邻居时，GraphSAGE 还能依赖什么产生输出？

### 学习完成证据

保存一份手绘/文本图和一个泄漏反例，并能逐边解释 fixture 的期望结果。

## 6. L2：PyG `Data`、`edge_index`、root node 与 batching（30 分钟）

### 要掌握的最小知识

- `x` 的每一行对应一个节点，列对应特征；
- `edge_index` 通常是形状 `[2, num_edges]` 的整数张量；
- 无向语义在消息传递中通常需要显式双向边；
- 节点编号只是局部索引，必须通过映射表追溯到业务实体；
- 本项目对根交易节点计算分类 loss，其他节点提供上下文；
- 将多个 ego graph batch 在一起时，要保存每个样本 root node 的偏移后索引，不能默认根总是第 0 行。

### 对照项目阅读

- 路线 1 产生的图 fixture 和期望边表；
- 路线 2 的[图产物契约](../data/stage-04-graph-artifacts.md)、[验收与复盘](../../reports/stage-04-route-2-artifacts.md)、节点映射和 manifest；
- Stage 01 的 Parquet schema 校验方式，用于对比“表格契约”和“图契约”。

### 动手任务

对一个最小 ego graph，手写并核对：

```text
node_id → node_type/business_id
x.shape
edge_index.shape
root_node_index
target label（只供 loss）
```

把两个图组成 batch，检查第二个图的 root index 是否正确偏移。故意删掉一条反向边，观察一层消息传递方向发生什么变化。

### 自测问题

- 为什么节点映射顺序必须稳定？
- `edge_index` 中出现一条边，是否自动代表无向关系？
- 为什么 batch 后不能继续假设每个样本根节点索引都是 0？
- manifest 为什么要保存 feature dimension 和 node-type 规则？

### 学习完成证据

用自己的话解释 fixture 的四个核心张量/索引，并能定位一次 root 对齐错误。

## 7. L3：GraphSAGE、损失、类别不平衡和 early stopping（60 分钟）

### 要掌握的最小知识

- 两层 GraphSAGE 让根节点接收最多两跳上下文；层数越深不一定越好，可能增加计算和过平滑；
- sigmoid 把 logit 映射到 0～1，但这不自动意味着概率已校准；
- `BCEWithLogitsLoss` 在数值上比先 sigmoid 再 BCE 稳定；
- 欺诈正例少，训练权重只能用训练标签计算；
- mini-batch 和 fanout 控制显存/内存，但采样规则会改变模型看到的信息；
- early stopping 观察验证 PR-AUC，不观察测试集；
- 小 fixture 过拟合用于验证实现，不能当作泛化能力。

### 对照项目阅读

- `src/graphrisk/models/tabular.py`：Stage 02 如何处理类别权重和分类模型；
- `src/graphrisk/training/train_baselines.py`：模型选择、指标和 artifact metadata；
- 路线 3 的[GraphSAGE 训练契约](../data/stage-04-graphsage-training.md)与[训练曲线复盘](../../reports/stage-04-route-3-training.md)、forward、训练循环和 checkpoint 保存逻辑。

### 动手任务

1. 选一个根节点，写出两层后它最多能接触的节点类型；
2. 用一个正例、一个负例的 logit 计算 sigmoid，并判断哪个 loss 更大；
3. 在小 fixture 上训练到几乎完全拟合，确认 loss 下降和参数变化；
4. 观察一次真实训练曲线，标出训练 loss 继续下降但验证 PR-AUC 不再改善的位置。

### 自测问题

- 为什么输出 `0.8` 不能写成“80% 确定欺诈”？
- `pos_weight` 应该从哪个 split 计算？
- 为什么最佳 epoch 由验证集决定，而测试集只运行冻结模型？
- fanout 减小会同时影响什么资源和信息？
- GraphSAGE 指标低于 XGBoost 时，什么证据仍能证明本阶段有价值？

### 学习完成证据

写一段 5～8 句的训练曲线解读，包含 loss、验证 PR-AUC、最佳 epoch、过拟合迹象、实际设备和分数未校准限制。

## 8. L4：PR-AUC、公平比较与简单融合（30 分钟）

### 要掌握的最小知识

- 高度不平衡数据中，Accuracy 很容易被大量负例抬高；
- PR-AUC 更关注正例检出质量，是本项目主要指标；
- ROC-AUC、F1、Precision、Recall 和 Top-K 指标回答不同问题，不能互相替代；
- 模型比较前必须对交易 ID 做一一对应检查；
- 融合权重属于超参数，只能在验证集选择；
- 两个未校准分数的加权结果仍是未校准风险分数。

### 对照项目阅读

- `PROJECT_PLAN.md` 第 6 节的模型原则；
- Stage 02 验证报告和真实 IEEE-CIS 指标；
- 路线 4 生成的[同 ID 比较契约](../data/stage-04-model-comparison.md)与[真实对比报告](../../reports/stage-04-route-4-comparison.md)；从 `artifacts/stage-04/ieee-cis/comparisons/same-id-v4/validation-predictions.parquet` 抽 10～20 行练习核对 ID 与融合公式。

### 动手任务

从验证预测中抽 10～20 行，检查 XGBoost、GraphSAGE 和标签是否按相同 `transaction_id` 对齐。手算两个不同 `alpha` 下的融合分数，说明为什么只能用验证集决定选哪个。

### 自测问题

- 两个模型测试行数相同，为什么仍不代表比较公平？
- 为什么不能看到测试 PR-AUC 后重新选择 `alpha`？
- GraphSAGE PR-AUC 更低，但 Recall@Top-K 更高时应该如何表述？
- 受控 50k 实验为何不能和 Stage 02 全量指标混成一张无说明排行榜？

### 学习完成证据

用 3～5 句话解释最终对比表，既说明最优结果，也说明数据规模、同 ID、未校准和测试集边界。

## 9. L5：图风险邻居、离线在线一致性与证据边界（30 分钟）

### 要掌握的最小知识

- 训练产物不只是权重，还包括特征预处理、图 schema、数据源、时间范围和模型版本；
- 在线/工具侧必须使用与训练相同的特征顺序、节点类型和采样语义；
- 历史共享实体是可验证关系事实，图风险分数是模型输出，两者应分字段呈现；
- 高分邻居不等于已确认欺诈，更不证明目标与邻居属于同一个真实用户；
- in-sample 训练分数可能过于乐观，不能无说明地当成独立邻居证据；
- embedding 表示模型内部相似性，不能直接当作人类可读原因。

### 对照项目阅读

- `src/graphrisk/investigation/contracts.py` 中 `RiskyNeighbor` 与 `RiskyNeighborsData`；
- `src/graphrisk/investigation/relation_tools.py` 中真实图工具及未注入服务时的 Stage 03 兼容状态；
- `src/graphrisk/investigation/risk_tool.py` 的数据源和模型 artifact 门禁；
- 路线 5 的[图服务契约](../data/stage-04-graph-service.md)、[真实验收记录](../../reports/stage-04-route-5-graph-service.md)、`src/graphrisk/graph/service.py` 与邻居查询测试。

### 动手任务

挑一个工具输出，对每个字段标记来源：直接边表、模型预测、模型 metadata、请求参数或派生排序。再写出一句合格结论和一句越界结论，例如：

```text
合格：该历史交易与目标共享 card，GraphSAGE 风险分数为 0.74，分数未校准。
越界：该 card 属于诈骗团伙，因此目标交易确定为欺诈。
```

### 自测问题

- 为什么模型文件存在仍可能拒绝服务？
- 没有合格风险邻居为什么应返回空 `ok`，而不是伪造一个邻居？
- 模型版本匹配但图 manifest 数据源不匹配时应发生什么？
- 为什么共享 card 是证据，而“同一真实用户”不是已证实事实？

### 学习完成证据

能够逐字段解释一份 `find_risky_neighbors` 输出，并指出它能支持和不能支持的结论。

## 10. L6：工具失败、部分报告与工作流恢复（15 分钟）

### 要掌握的最小知识

- `not_found`、`unavailable`、`dependency_error` 和空成功表示不同业务状态；
- 图能力是调查证据的一部分，其失败不应抹掉已成功的交易、特征、XGBoost 和直接关系证据；
- 报告内容与运行审计分离，才能保持业务结果确定性；
- 错误输出应可行动，但不泄露磁盘路径、堆栈、密钥或完整原始行。

### 动手任务

画出三条分支：

1. 目标交易不在数据中；
2. 交易存在，但图模型 artifact 缺失；
3. 图模型正常，但没有历史风险邻居。

分别标出工作流是否停止、报告状态、仍保留的证据和工具错误码。

### 自测问题

- 哪个场景应在第一个工具后停止？
- 图模型失败时为什么 XGBoost 结果仍可保留？
- 空邻居与图模型不可用有何区别？

### 学习完成证据

能够不看代码说清三条分支，并与自动化测试结果一致。

## 11. L7：结果复盘与求职表达（30 分钟）

### 要掌握的最小知识

面试表达需要连接业务问题、数据边界、技术选择、验证证据和已知限制。不要只说“我用了 PyG 和 GraphSAGE”，也不要只报一个指标。

建议使用以下结构：

```text
问题：交易调查缺少关系风险证据
约束：IEEE-CIS 实体是匿名映射，且任何预测只能看到严格历史
方案：时序 ego graph + 两层 GraphSAGE + 版本化图工具
验证：防泄漏 fixture、同 ID 模型比较、失败恢复、真实调查
结果：如实报告 XGBoost/GraphSAGE/融合指标和延迟
限制：受控规模、未校准分数、本地图索引、实体并非真实用户身份
```

### 动手任务

准备三种长度的表达：

- 30 秒：项目目标和你的核心贡献；
- 90 秒：时间泄漏、模型比较和 Agent 工具接入；
- 3 分钟：加入失败案例、指标、权衡和下一阶段。

再回答一个逆风问题：“如果 GraphSAGE 不如 XGBoost，为什么还保留它？”回答应基于图证据能力、失败边界和实测结果，不能声称不存在的提升。

### 自测问题

- 你如何用一个测试证明未来边没有泄漏？
- 为什么选 GraphSAGE 而不是更复杂的 GAT/异构 GNN？
- 你的图工具比直接 SQL 共享实体查询多提供了什么？
- 当前设计离生产系统还缺什么？

### 学习完成证据

录下或写出一份 90 秒讲解，必须包含一个具体时间门禁、一个指标比较、一个失败恢复行为和一个限制。
