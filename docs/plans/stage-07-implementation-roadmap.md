## 目标与不变约束

从[Stage 06 总验收](../../reports/stage-06-route-7-acceptance.md)出发，保留已通过的真实交易调查、50 个冻结案例、API/工作台和本地/Compose 演示。Stage 07 交付：可追踪的请求链、可从进程重启恢复的报告与人工审批、PostgreSQL 持久状态、可切换且有出处校验的 pgvector 政策检索、至少 12 个新增的非重复挑战案例及 Agent 评估 v2。两周时间是目标，不是删减验收的理由。

`run_id`、`session_id`、报告哈希、政策日期、错误码和审批绑定的对外语义原则上保持；如必须改变，先写兼容方案和回归测试。正常演示仍由单机本地路径保底，数据库模式通过显式配置选择，不能在数据库不可用时悄悄退回内存并声称完成持久化。仅从批准/拒绝生成审计，不增加自动封禁、拒付或通知。`reviewer_id` 目前未认证，Stage 07 不能把请求 ID 或持久化误写成正式身份认证；限制对外展示时继续明确标识。

PostgreSQL/pgvector 是本阶段**必过门禁**：要有真实数据库容器、迁移、查询、重启恢复及测试证据。Neo4j 仅为可选扩展，不作为完成条件；16 段模拟政策规模很小，pgvector 可先使用精确距离查询，不为展示而强加 ANN 索引。使用现有依赖和标准库能满足时不引入新框架；数据库驱动/检查点适配包须在路线 0 验证兼容性和锁文件后引入。原始 IEEE-CIS、标签、密钥、模型权重、生成报告不提交 Git。

## 路线 0：前置门禁、基线和选型

**实现目标。** 核对 Python 3.11、`uv.lock`、Docker Engine/磁盘空间、固定 Ollama digest、Stage 06 的本地与 Compose 就绪。重跑全量测试、冻结 50 案及三条真实本地样本；记录旧 17/新 33 案 SHA-256、政策语料/索引版本、GraphSAGE 比较运行和固定 held-out 交易的 0 邻居事实。盘点 `Stage06Service` 内存记录、`CostLedger`、`InMemorySaver`、`PolicyRetriever` 的边界。用最小探针比较可用的 LangGraph 持久检查点适配与 PostgreSQL 驱动，确认 Python/锁文件、容器镜像、pgvector 扩展和 Ollama embedding 维度；版本与镜像摘要在执行时固定，不在计划里猜版本。只有证据支持时才选择依赖。

**学习任务 L0（1h）。** 画出 Stage 06 的内存状态图，分别指出“报告存在”“检查点存在”“费用已计入”在崩溃时可能如何不一致；解释为什么固定 50/50 不能证明没有长尾失败。

**门禁。** 前置矩阵含实际命令、版本、磁盘与阻塞；基线报告可复跑；选型文档写清检查点、运行记录、费用和 pgvector 的最小依赖及回退方案。若 Docker/模型/锁文件不通过，路线 4、5 不开始。

## 路线 1：失败分类、挑战集与评分契约

**实现目标。** 从 Stage 06 结果、代码风险和故障注入列出“真实观察”“模拟触发”“仅推测”三类。旧 48/50 初跑的两项是**评估器误判**，不能记成 Agent 失败。新增至少 12 个有不同失效机理的案例，覆盖：进程重启待审恢复、重复/冲突审批、过期、数据库断连和写入中断、费用重复扣减、政策版本/日期/引用错绑、向量维度错配、图邻居为空/图服务失败、请求链丢失、模型不可用或超时。按开发集与冻结验收集分开；旧 50 案原文件、SHA 和期望均不改。记录每例输入、预期工具/参数、证据集合、业务/HTTP 分支、审批状态、错误码及评分依据。若找到第二笔有真实历史图邻居的 held-out 交易，可作为补充演示，但先核对测试集归属和时间边界；找不到就记录 0 邻居限制，不用标签挑样本。

**学习任务 L1（1.5h）。** 对 6 个候选失败写“触发→正确安全结果→可观测证据”；手动区分评估器缺陷、产品缺陷、环境故障。解释为何新冻结集应在修改工作流前确定。

**门禁。** 新案例数和独立风险点可审计，旧 50 案哈希不变；评分脚本能把故意破坏的引用/绑定判为失败且保留逐例失败。初始通过率如实报告，不在冻结集上反复调阈值。

**执行结果（2026-09-28）。** [路线 1 报告](../../reports/stage-07-route-1-failure-contract.md)记录 15 个冻结/3 个开发案例、旧 50 哈希、三类失败来源和评分规则。真实 API 重启探针使冻结集 1 已观察、0 通过、1 失败、14 `not_run`；引用/日期/绑定突变测试与 310 项全量回归通过。未运行的数据库、pgvector 与追踪案例不算通过；个人 L1 自测未代签。

## 路线 2：请求 ID、工具轨迹与安全审计

**实现目标。** 每次 HTTP 请求由服务端产生/规范化请求 ID，在 API 响应头、结构化日志、调查运行和工具事件中关联；`run_id` 仍是业务调查 ID，`request_id` 标识一次 HTTP 调用，重读与审批可有不同请求 ID。日志只记时间、ID、阶段、工具名、状态、错误码、耗时和模型/索引版本，不记测试标签、原始行、密钥、完整 Prompt 或政策全文。保留 Stage 06 审计对外字段与错误分类的兼容性。仅建立轻量追踪字段，不提前做 Stage 09 的指标平台或监控面板。

**学习任务 L2（1h）。** 手绘一次创建→检索→生成→审批的两级关联；给出一个不能把客户端自报 ID 当认证身份的反例，并解释日志脱敏边界。

**门禁。** fake 依赖和真实本地请求均能用 `run_id` 与请求 ID 找到工具事件；并发请求不会串号；错误/无政策路径也有链路；测试断言受限字段不进入日志。现有 API 和工作台回归通过。

**执行结果（2026-09-28）。** [路线 2 报告](../../reports/stage-07-route-2-request-trace.md)与[请求链契约](../data/stage-07-request-trace.md)记录：服务端请求 ID 贯通创建/读取/审批、工具事件与受限日志；fake 并发/无政策/错误/脱敏及真实本地 held-out 复核通过，冻结追踪挑战 1/1 通过。全量 316 项回归通过；重启挑战仍失败，另外 13 条新冻结案例 `not_run`。个人 L2 自测未代签。

## 路线 3：持久化、恢复与兼容合同

**实现目标。** 先定义可持久的运行快照、报告哈希/版本、审批检查点及决定审计、费用预留/结算、TTL 和模式标识。写明“先建检查点后发布 pending”的提交顺序、失败时的补偿或重试对账；不能出现有可审批 API 记录但无检查点的状态。保留 `run-{instance}-{uuid}` URL 形状；持久模式按数据库记录查找，不能仅因新进程的 instance ID 不同就报错。旧内存模式运行在新进程确实不存在时仍须明确失效，不伪装恢复。规定重启前后相同报告哈希、相同审批窗口、重复同一决定幂等、冲突决定拒绝、到期不恢复、数据库不可用时 fail-closed。冻结迁移策略：数据库 schema 版本、可重入迁移、升级/回滚规则和过期清理；不能把测试标签或原始 CSV 复制进数据库。

**学习任务 L3（1.5h）。** 为“生成后崩溃”“检查点写入失败”“决定写入成功但 HTTP 响应丢失”“两人同时决定”写状态表，标注事务边界与幂等键。区分进程重启恢复和多 worker 并发安全；没有并发证据前继续单 worker。

**门禁。** 契约文档及故障矩阵可直接转化为测试；至少覆盖恢复、过期、错哈希、冲突、重试、费用重复扣减、数据库断连。路线 4 不在合同未冻结前修改运行状态结构。

**执行结果（2026-09-28）。** [持久化/兼容合同](../data/stage-07-persistence-contract.md)和[故障矩阵](../data/stage-07-persistence-fault-matrix.md)已冻结：内存与 PostgreSQL 显式模式、运行/审批/费用状态、checkpoint-first 发布、决定意图与补偿、TTL、幂等键、迁移/清理和错误映射；P01～P15 可直接作为路线 4 真库测试输入。[路线 3 报告](../../reports/stage-07-route-3-persistence-contract.md)记录一致性核查。此路线仅关闭**设计合同门禁**，数据库实现和恢复验收仍未完成；个人 L3 自测未代签。

## 路线 4：PostgreSQL 运行记录、检查点与审批恢复

**实现目标。** 增加显式启用的 PostgreSQL 后端、版本化迁移与最小权限配置。持久化 `InvestigationRecord` 的安全必要字段及版本/报告摘要、审批暂停/恢复所需 LangGraph 状态、独立决定审计与费用账本；事务或幂等补偿保证对外 `pending` 必有可恢复检查点。用唯一键/条件更新保证同一决定幂等，冲突和过期仍按 Stage 06 错误码返回；对费用预留及结算避免同一请求重试重复计费。进程停止不能删除未到期的持久状态；清理按 TTL 保留审计所需最小记录。数据库故障时返回结构化不可用状态，不退回 `InMemorySaver` 并声称恢复。

**学习任务 L4（2.5h）。** 亲手在测试库查看一次 `pending` 的记录、检查点与费用行；重启 API 后按相同 `run_id` 取回，再完成拒绝。解释唯一约束、事务隔离/条件更新和崩溃补偿各负责什么。

**门禁。** 真 PostgreSQL 集成测试完成“创建 pending→停 API→新进程 GET→拒绝→重复相同决定→冲突决定”“生成/保存中断”“审批并发”“TTL/错哈希/版本错绑”“DB 掉线”。报告哈希不变，外部动作 0，费用不重复计入；现有本地模式不回退。迁移可从空库重复执行，不把连接串写入 Git。若 LangGraph 持久检查点适配不兼容，保留阻塞并修复，不把仅保存报告 JSON 当成会话恢复。

**执行结果（2026-09-28）。** [路线 4 真库报告](../../reports/stage-07-route-4-postgres-recovery.md)与[操作说明](../data/stage-07-postgres-service.md)记录：PostgreSQL 业务表和 PostgresSaver 检查点、显式双模式、创建幂等/费用账本、决定意图/崩溃恢复、TTL/迁移/清理和受限角色已落地。12 项路线 4 真库集成、真实 IEEE-CIS held-out 跨实例拒绝、冻结重启案例通过；全量 329 项回归通过。冻结 v2 当前 2 通过/13 未运行，Compose 容器重建与 pgvector 尚待路线 5～7；个人 L4 自测未代签。

## 路线 5：pgvector 政策检索的可切换实现

**实现目标。** 基于现有 16 段原创模拟政策与固定 `chunk_id` 建表，以 `(index_version, chunk_id)` 唯一键保存出处、版本、正文哈希、生效区间、embedding 模型 digest/维度和向量；导入可重跑且不能混入另一个模型版本。查询先执行半开日期过滤，再按余弦距离召回，按稳定 `chunk_id` 打破并列；本地 dense 检索的阈值、文本重合门禁、`no_active_policy`/`no_match` 和结构化 `RetrievalResult` 保持。向量维度、来源哈希或索引版本错误时拒绝输出引文。通过显式配置选择 pgvector；Stage 06 的 TF-IDF 默认路径继续可运行，是否升级默认后端由质量对照决定。16 段规模先用精确检索，ANN 索引只在有性能证据时做。

**学习任务 L5（1.5h）。** 用一条跨版本政策解释为何必须先按日期筛选，再取 Top-K；手算两个归一化向量的余弦排序，解释检索相似度不是风险概率或政策适用概率。

**门禁。** 真 pgvector 的来源/日期/维度/并列排序/无答案/错误测试通过；用同一 embedding 输入对照现有 `local_embedding` 的候选与顺序，并报告 Recall@3、无答案率、引用完整率和 P50/P95。任何来源或无答案回归均阻止切换；数据库故障时不能编造片段。

**执行结果（2026-09-28）。** [路线 5 真库与质量对照](../../reports/stage-07-route-5-pgvector.md)和[操作/数据合同](../data/stage-07-pgvector-retrieval.md)记录：16 段固定 dense 索引重复导入、受限只读查询、日期先筛/余弦排序、模型/来源/维度/故障拒绝均通过。30 条固定查询的本地 dense 与 pgvector 状态和候选 ID/顺序差异 0；两组 Recall@3 1.0、无答案误报 0/4，pgvector P50 更高，故 TF-IDF 仍为默认。真实 held-out 调查返回 `verified/pending` 与 3 条 pgvector 命中；全量 334 项测试通过。Compose 拓扑和 Agent v2 全集仍待路线 6～8；个人 L5 自测未代签。

## 路线 6：有界 Agent 修复与 Agent 评估 v2

**实现目标。** 只针对路线 1～5 暴露的实际缺陷或新增开发案例调整工具描述、状态流转、恢复与终止规则；不得放宽最大步数/工具调用/时间/费用限制掩盖失败。保留未修改的旧 50 案和冻结新案例，执行至少 62 案并按风险分组报告；对原 Stage 06 的三条固定真实本地样本用相同模型 digest、交易、政策日期和关系上限复测。若有新增图丰富的测试交易，单独报告，不混为同一基线。比较工具/参数正确率、引用完整率、无依据结论、审批绕过、恢复成功率、P50/P95、Token/估算费用与逐例失败；fake 和真实模型分开。

**学习任务 L6（1h）。** 选一项修复做“失败证据→最小代码变化→新旧案例结果”的复盘；解释旧 50/50 饱和时为什么更要看新挑战、失败安全性和真实样本。

**门禁。** 旧 50 案继续 50/50，新 ≥12 案的预期安全分支全部通过；无依据政策结论 0、审批绕过 0、外部动作 0；实际失败不得删除。真实模型样本报告保留版本与失败，并明确小样本限制。没有达到条件则路线 6 未完成，不把 v2 写成改善。
