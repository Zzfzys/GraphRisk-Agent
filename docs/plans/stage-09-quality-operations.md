# Stage 09：CI、可观测性与可靠性

> 状态：Planned  
> 计划时间：Week 13～14  
> 前置阶段：Stage 06

## 阶段目标

建立持续验证和运行可观测能力，使代码、模型和 Agent 改动能够被自动检查。

## 实现任务

- [ ] 配置 lint、单元测试、集成测试和 API 测试；
- [ ] 配置 GitHub Actions；
- [ ] 在适合的环境验证 Docker build；
- [ ] 记录请求延迟、错误率、模型版本和风险分布；
- [ ] 记录 LLM 模型、Token、成本和工具失败；
- [ ] 建立基础数据漂移和输出漂移报告；
- [ ] 建立回归评估，防止 Prompt 或工具变更破坏已有案例；
- [ ] 完成密钥、日志脱敏和 Prompt injection 检查。

## 交付物

- CI workflow；
- 测试策略文档；
- 可观测性字段说明；
- 回归评估报告；
- 基础安全检查报告。

## 验收标准

- [ ] Pull request 或 push 能自动运行核心检查；
- [ ] Agent 评估具有可比较的历史结果；
- [ ] 单次调查可以关联 API、模型、LLM 和工具事件；
- [ ] 日志不包含密钥或未脱敏的敏感字段；
- [ ] 关键失败可通过日志定位。

- CI 无法运行 GPU 测试：使用小型 CPU fixture，完整训练在本地执行；
- 监控范围膨胀：保留结构化日志和离线报告，高级仪表盘后置；
- 漂移样本不足：使用可控合成扰动验证流程。
