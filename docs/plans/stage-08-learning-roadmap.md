# Stage 08 学习路线：一边实现一边理解

> 状态：路线 0～8 学习材料已就绪；L0～L8 个人自测尚未完成

> 约 12 小时定向学习，分散在两周 20～24 小时/周的项目时间内；每天至少 30～60 分钟

## 学习方法

每条路线按“先预测 → 读现有代码/官方契约 → 做一个最小实验 → 对照真实输出与测试 → 用自己的话解释”执行。AI Agent 可以协助编写和查错，但你的笔记必须能回答**为什么**某条证据足够、某个失败必须拒答。每次笔记记五栏：日期/路线、预期、所用输入与命令、实际结果、我的解释与疑问。只记录可公开的模型 ID/digest、案例 ID、汇总指标和模拟文档引用，不贴 API 密钥、原始 IEEE-CIS 行、完整私有 Prompt 或连接串。

路线 0～4 预计占第 1 周约 20 小时，路线 5～8 第 2 周约 24 小时。学习约 12 小时，剩余约 32 小时用于实现、测试、修复与文档。以下自测须你本人实际操作，工程测试不能代签。

| 学习项 | 对应路线 | 学习时间 | 核心问题 |
|---|---|---:|---|
| L0 证据边界 | 0 | 0.5h | 哪些案例能比较真实模型，哪些数据能出本机？ |

| L5 混合检索 | 5 | 1.5h | 文本相似与图路径何时互补？ |
| L6 受证据约束的 Agent | 6 | 1.5h | 何时回答、何时拒答、如何防注入？ |

## L2：6GB 显存、量化与推理测量（1.5h）

**先读。** 当前固定 Ollama 配置与[生成接口字段](https://docs.ollama.com/api/generate)、[运行模型资源字段](https://docs.ollama.com/api/ps)。

**亲手练习。** 对已有 0.5B 基线和一个候选先预测显存与首 Token 延迟，再观察固定 digest、量化、上下文、`size_vram`、冷启动和热运行。把模型加载时间、Prompt 处理时间与生成时间分开记；若 CPU 降级，要明写原因和速度。

**自测。** 为什么“模型文件小于 6GB”并不保证 6GB 显存能稳定运行？P95 高时，先区分加载、上下文、生成和资源争用中的哪一项？

**L2 实作入口。** 阅读[本地测量合同](../data/stage-08-local-measurement.md)，先用参数量 × 每参数位数 / 8 估算权重字节数，再说明量化元数据、KV cache、运行缓冲为何另占空间。运行 `uv run --offline python scripts/measure_stage08_local.py` 前须确认配置中的两个固定模型已安装、Ollama 空闲。从生成 JSON 的 cold/warm 行手算生成 Token/s = eval_count / (eval_duration / 1e9)，并与 wall_ms 对照；说明为什么五次重复提示词不能代表不同用户请求的 P95。本入口不测首 Token 延迟。真实结果和失败见[路线 2 记录](../../reports/stage-08-route-2-local-model.md)；学习自测仍由本人填写。
