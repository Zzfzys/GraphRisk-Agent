## 路线 0：前置门禁、版本冻结与实验合同（3h）

**目标。** 找到实际加载版本，冻结初始 Agent 和模型，防止讨论旧分数却实测新权重。

**步骤。**

1. 复核 Stage08 与最新 Docker 恢复记录；检查 Python/锁、Ollama/digest、图/政策工件、Docker/隔离 DSN、内存/显存/磁盘。最小依赖探针不自动训练。
2. 解析 Stage05/Stage07 配置和运行器，绑定实际 checkpoint、图 manifest/encoder、同 ID 比较文件、XGBoost champion、政策日期/版本、retriever、schema/Prompt 与 LLM 参数，记录内容哈希；缺失或错配明确失败。
3. 以当前 metadata 为训练证据：batch 256、50 epoch、patience 20、最佳 6、停止 26，区别于早期 batch 128、20 epoch、patience 4。具体服务绑定再次确认，不修改旧 YAML/权重。
4. 冻结数据用途：train/validation 用于图诊断，验证期交易用于 Agent 工程质量，test 只用于最终固定方案复核。列出历史测试已观察记录；全测试曾报告过，不能称完全未见。
5. 冻结 30 笔、至少 20 笔实际尝试生成；并发 1、沿用每案最多 2 次生成、300 秒整体/180 秒单次上限。路线 1/5 各 30 首次+3固定重复，共最多 132 次生成尝试；最多 5 个开发探针（10 次）+1 次预热（2 次），阶段上限 144 次。确定性停止不强行调用；到限停止并记 not_run。
6. 冻结图训练候选/种子/指标/选型/停止线、目录与资源阈值。空闲测量后制定阈值，不足则暂停，不关闭系统分页或并行硬跑。

**学习 L0。** 分清 YAML、metadata、实际加载权重，解释测试已观察的限制。

**交付。** 实施时创建 `docs/data/stage-09-experiment-contract.md`、`reports/stage-09-route-0-preflight.md`，版本链、用途/预算表与新目录。

**验收。** 所有实际工件可按清单核对；预算/分母/用途冻结。依赖未恢复或工件不匹配不进入真实基线。

## 路线 1：多交易真实本地 Agent 基线（7h；工程证据完整/人类复核待完成）

**目标。** 从同交易三个场景扩展到 30 笔不同交易的真实调查记录。先测量，测量过程中不改 Prompt、LLM、重试或评分规则。

**步骤。**

1. 新建独立评估入口，复用当前调查服务/工具与 Ollama provider；旧 `evaluate_stage06_agent.py --real` 的三个同交易样例不是新集。fixture 验证去重、预算、停止、计数和评分，不算真实成绩。
2. 在验证期候选按固定 XGBoost 分数分位层选低/中/高各 10 笔，30 个不同 ID；这是排序分层，不是校准业务风险。尽量覆盖至少 20 笔当前图覆盖目标、至少 5 笔有合法历史邻边、至少 5 笔缺失/无历史/图不覆盖等边界（属性可交叉）。不按标签或生成结果挑选；候选不足，生成前写明真实数量及确定性替补规则，不虚构边。
3. 为冻结交易建立权威工具快照与约束：交易/历史、模型分数与版本、关系、政策日期/出处/适用条件、允许动作。证据不足允许正确拒答或不确定；欺诈标签不作 LLM 解释真值。
4. 看输出前冻结 ID/分层/快照/评分器哈希，清单与原始输出只在本地受限目录。政策日期沿用模拟语义，不把 IEEE 相对时间解释为真实业务日历。
5. 顺序运行 30 笔，至少 20 个不同交易实际尝试本地生成；模型失败不换模型/托管 fallback，保留安全本地记录、错误与尝试数。三个预定样例再跑一次作稳定性观察，不增加独立样本分母。
6. 评分分执行/结构、事实/引用/政策条件、失败安全/审批三层。机器检查全案例，再人工核对至少 10 案及全部可疑发布结果；按固定规则核对事实和建议依据，不能把流畅或 `verified` 自动算正确。
7. 输出总例数、不同交易、生成交易、尝试、确定性停止、not_run；分别报完整/部分/正确拒答/失败。冷/热延迟及失败耗时分开，Token、资源、超时一起记录。P95 只代表这些小样本。

**学习 L1。** 手算分母；解释 fake 与真实模型、拒答与失败、结构与语义的差别。

**交付。** `reports/stage-09-route-1-real-agent-baseline.md`、受限冻结清单、逐例评分、人工核对表与调用/资源账本。

**验收。** 30 个不同交易全部有真实观察或确定性停止，0 not_run；至少 20 笔尝试本地生成；版本不变、失败保留。质量可能不合格，但不能遗漏失败。发现伪造依据发布/审批绕过先隔离修复、新运行复测，首轮记录保留。

**下一步门禁。** 基线输入、真实调用与失败归因完整即可进入 GraphSAGE，不要求先把小模型调到高成功率；基线未补齐不得抢先做大规模调参。

## 路线 2：GraphSAGE 实现、梯度与两跳传播审计（3h；工程Done/L2待完成）

**目标。** 证明预期两层 GraphSAGE 的根预测确实利用历史信息，加载/推理成功不足以证明实现正确。

**步骤。**

1. 审计 `graph/model.py`、`schema.py`、训练与 batch/root：SAGEConv、激活/dropout、边方向、根索引/图隔离、logit/BCE/pos_weight、train/eval、optimizer、早停恢复和加载。
2. 手工“当前交易→实体→历史交易”图核对两跳计算。固定有效非零权重，对历史特征扰动应沿合法路径影响根；超出两层感受野的特征不应影响根。随机零权重/ReLU 不变不能直接判实现错。
3. 小图过拟合、梯度/参数更新、单图与 batch 输出一致性；标签只进入 loss，不进特征/sampler，不要求所有张量梯度必非零。
4. 重跑未来/同时间/占位/乱序边界，检查历史节点特征按历史节点自己的时间截止，不能按目标时刻回填。
5. 有 bug 先失败测试再最小修复，新版本/工件独立保存，说明旧基线影响；无 bug 记录确认的具体项目。

**学习 L2。** 手画消息与根索引，解释管线错误为何仍能训练。

**交付/验收。** `reports/stage-09-route-2-graphsage-audit.md`、有效正确性测试和必要修复；列确认/缺陷/未验证，消息路径和更新通过后做采样诊断。

## 路线 3：采样、时间边界与同特征基线（3h）

**目标。** 解释真实图内容，用公平对照区分图结构价值和模型容量。

**步骤。**

1. 核实 `fanout: [10,5]`：现有契约是四类根实体、每实体最多五笔较早交易，不能照名称称标准逐层 NeighborLoader。统计实际邻居/节点/边、缺失、度数、无边、冷启动和时间分层。
2. 核对 ID、encoder 仅 train 拟合、训练图无未来关系。说明推理是否用已发生的更早 validation/test 事件作无标签上下文，与既有在线时间策略一致并写 manifest。
3. 固定实际 50k/10k train/validation 清单、根交易特征、预处理/缺失和标签，建立 XGBoost 与 MLP 对照。Stage02 full-data 模型另表，不能和小训练 GNN 直接归因。
4. “同特征对照”和“各模型业务特征”分开；类型特征明确，MLP 只得到根交易特征。新增训练/比较入口先支持 validation-only。
5. 当前采样与一个较大历史上限候选保持目标/特征不变，扩大图新建 manifest/目录，训练/推理一致，测覆盖/内存/耗时；不改参数后偷偷复用旧图。

**学习 L3。** 实体启发式不等于客户身份；同 ID 为何仍可能不公平。

**交付/验收。** `reports/stage-09-route-3-sampling-baselines.md`、采样统计与同特征验证结果。时间/标签/特征边界通过才做效果调参。

## 路线 4：消融、有限调参与模型决策（6h）

**目标。** 在有限预算内诊断实现、特征、关系、采样、过拟合和时间迁移，不保证超过 XGBoost。

**冻结对照。**

| 实验 | 控制不变 | 改变/问题 |
|---|---|---|
| MLP / 同特征 XGBoost / GraphSAGE | 目标、时间、根特征 | 模型与结构价值 |
| GraphSAGE 完整图 / 去边 | 节点、特征、训练预算 | 关系是否有效 |
| 完整图 / 受控扰乱边 | 类型、合法历史、预算 | 真实关系或连接数量 |
| 完整特征 / 去历史统计 | 拓扑、目标、预算 | 历史数值贡献 |
| 当前 / 较大历史采样 | 目标、特征、参数 | 稀疏采样限制 |

去边仍有自变换，不自动等于 MLP；扰乱只能在合法历史内按类型重连，保持预定计数/根目标/时间。无法合法实现就明确未执行，不制造泄漏。关系消融各自重训；旧权重删边只算敏感性，单列。

**步骤。**

1. 先复现当前 checkpoint 的验证预测，核对 SHA256/encoder/评分与 Stage05 比较，旧历史分数不硬凑一致。
2. 一次一项改变，统一 PR-AUC/AP 的实际公式与 ROC-AUC；连同正例率、Precision/Recall@Top1%/5%、曲线、最佳轮数、资源/时间报告。sigmoid 仍是未校准分数。
3. bug 先修。最多 6 个预注册组合，例如 lr 0.001/0.0005、dropout 0.2/0.4、hidden 64/128 的有限组合；每次最多 50 epoch、patience 10，不覆盖旧 YAML。路线 0 按空闲资源冻结单次与总墙钟停止线；不可承受就停止记未运行，不改目标集。
4. 最多 5 个新增 GNN 基础/消融训练、6 个候选、最佳配置追加两个预定种子，总计最多 13 次新增 GNN 训练；完全相同已执行运行可复用。MLP/XGBoost 各最多一次基础对照。所有种子/选择规则先登记。
5. 最佳候选共三个种子，检查早/晚验证与图覆盖群体，报告均值/波动/配对差异。相关交易、小样本、反复验证限制区间解释，不伪称显著。
6. 只按 validation 选方案，融合也只在 validation 定权重。旧 `compare_graphsage.py` 读取 test，不用于候选搜索；实施 validation-only 比较。冻结后至多一次批量测试复核，与旧方案同 ID/同指标，不据 test 再选下个候选。
7. 历史 test 已观察，最终称“已观察测试上的固定方案复核”。严格未见测试需新时间窗口与可验证访问记录；没有就写无法提供，重切旧数据不叫全新盲测。
8. 决策：保留当前、晋级新候选，或 XGBoost 默认评分+真实图关系证据+实验性 GNN。增益不足/不稳定/成本过高可以不晋级；预算耗尽是未验证，不是证明无增益。

**学习 L4。** 曲线/消融/种子解释；多 epoch 不证明充分，有限搜索不证明全局最优。

**交付/验收。** `reports/stage-09-route-4-graphsage-diagnosis.md`、完整实验清单、版本化结果与验证选型。基础对照、关系/特征诊断实际执行；缺证据调整排期，不提前完成。回答实现、传播、差距、默认模型和限制。

## 路线 5：模型决策接入与真实 Agent 同集重放（4h）

**目标。** 验证模型变化传到 Agent，把图模型效果与 LLM 效果分开。

**步骤。**

1. 版本化路线 4 决策，权重/encoder/manifest/比较文件错配拒绝；默认不用 GNN 时明确标注，不能把 XGBoost 单分数说成融合或隐藏图不可用。
2. 保持 30 ID、Prompt、schema、政策、LLM digest/参数/预算/评分不变；按模型决策重建工具快照，逐字段说明哈希差异。
3. 重放 30 首次+3固定重复，配对比较完成/部分/拒答、依据、调用、延迟/资源；同集诊断不说独立泛化，失败完整保留。
4. 若 LLM 仍差，提交失败矩阵与建议；Prompt/生成修复另立子实验，不与 GNN 变化混一轮，不自动加入模型下载或大规模重测。
5. fixture 验证切换、标签、图不可用与回滚，真实演示使用诚实模型组合。

**学习 L5。** 逐对解释模型差异与 LLM 波动。

**交付/验收。** `reports/stage-09-route-5-agent-replay.md`、逐 ID 配对与回滚；零伪造发布/审批绕过，模型质量不足独立标记，不拿 fake 补成绩。
