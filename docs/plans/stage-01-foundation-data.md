# Stage 01：工程骨架与时间正确的数据管线

> 状态：Planned  
> 计划时间：Week 1～2  
> 前置阶段：Stage 00

## 阶段目标

建立可维护的 Python 工程，并实现从原始交易数据到训练、验证和测试特征集的可复现管线。

## 学习任务

- Python `src` layout、依赖与配置管理；
- pytest、日志和异常处理；
- DuckDB、Parquet 与基础 SQL；
- 时间切分、窗口统计和 point-in-time correctness。

## 实现任务

- [ ] 建立源码、测试、配置、脚本、数据和报告目录；
- [ ] 建立配置加载与结构化日志；
- [ ] 定义交易、身份和图实体的数据契约；
- [ ] 实现原始数据校验与清洗；
- [ ] 按 `TransactionDT` 完成 70%/15%/15% 切分；
- [ ] 实现只使用过去信息的交易窗口特征；
- [ ] 输出 Parquet 特征集和数据质量报告；
- [ ] 为时间边界与泄漏场景编写测试。

## 交付物

- 可安装 Python package；
- 数据字典；
- 数据导入与特征构建命令；
- train/validation/test Parquet；
- 数据质量与时间泄漏测试报告。

## 验收标准

- [ ] 新环境可按照 README 运行测试；
- [ ] 同一输入与配置能够生成一致的数据切分；
- [ ] 历史窗口特征不包含当前或未来交易；
- [ ] 数据规模、缺失率、标签比例和时间范围有报告；
- [ ] 原始数据未被提交 Git。

## 风险与降级方案

- 16GB 内存不足：使用 DuckDB/Polars 风格的分批处理，避免 pandas 多份完整复制；
- 数据字段过于匿名：只对可解释实体建模，其余字段保留为模型特征；
- 真实数据延迟：使用同一数据契约下的合成数据替代。
