## L0：先分清我们已经证明了什么（60min）

读[路线 0 报告](../../reports/stage-10-route-0-preflight.md)、[证据台账](../data/stage-10-evidence-register.md)和[交付合同](../data/stage-10-delivery-contract.md)。先预测：971 是怎样组成的？为什么不能再加 26？为什么 50 个模拟案例不代表 50 笔真实模型成功？然后对照既有 acceptance 和报告。

用自己的话写下四项：工程通过、历史受限判断通过、当前增强配置质量仍待新实测、GraphSAGE 增量失败。检查总计划七项成功标准，圈出尚缺性能、冷环境、视频和本人复核的部分。产出一页“已证明/未证明”笔记；能解释 Stage 09 个人 Pending 与 Stage 10 开始不冲突才算本人完成。

## L1：设计一个不会误导自己的实验（75min）

先用 20 个手写耗时排好序，按合同的分位算法算 P50/P95/P99，再加入一个超时，比较“只看成功”与“全部请求”结论。解释 12 个真实样本为什么不适合宣传稳定 P99；无测量时延迟/Token 应为空而不是 0。

在路线 1 运行器实现后读计时和预算守卫：一个调查 run、一次模型 HTTP 请求、一次重试怎样计数？手算旧 130/144 余额 14，为 10 首次+2 固定重复留下 2 失败请求余量。解释为什么未知结果不能退款重发、Stage 08 的人民币余额不能直接转成新调用许可。

产出分位数手算、采样规则和预算流程图。预测冷启动、warm 和 unknown 各要什么证据；不按标签/成功挑样本。

## L2：顺着证据找到慢在哪里（120min，分 3～4 次）

先画一次请求：浏览器→API→交易/历史→评分/关系→政策→本地模型→报告校验→审批。为每段预测耗时，观察实际记录再比较。查看已冻结样本、版本、原始状态和重试；不能只读 passed 摘要。

比较无 LLM 快速接口、真实权重、真实 Agent 和历史回放。解释为什么回放读得快不代表模型推理快；keep_alive=0 可能让每次都加载，不能凭“第二次”就称 warm。读资源采样并区分进程 RSS、系统可用内存和显存；不了解整机峰值就不下保证。

产出一张按真实分组的延迟表、一个失败复盘和一项有证据的瓶颈判断。能指出当前配置质量的分母、未运行和出错项，再核对旧账本保持原样。

## L3：把模型结果讲准确（105min）

读[模型卡](../data/stage-09-5b-model-card.md)、[数据卡](../data/stage-09-5b-data-card.md)和路线 3 最终报告。解释 AP/ROC/Top-K 与正例率、同集合比较和人工时间锚。画三折时间线，指出训练/早停/校准/外层与历史已观察 test，为什么不能称新盲测。

手算融合 alpha=1 时谁提供分数，以及三折增量 0/正收益 0/3 为什么支持不晋级。说明 GraphSAGE 并未穷尽参数、单折有图优于无边不等于正式强基线融合有益。

再比较来源绑定、受限判断、引用核验、政策适用和欺诈真值；解释 GraphRAG hybrid 18/22、text 16/22 和机制 50/50 不是同一个分母。产出“能写进简历的三句话/不能写的三句话”，每句标来源。

## L4：从读者角度解释系统（90min）

读路线 4 README 和 Mermaid 图，沿一笔调查把所有箭头讲清。指出主评分来自谁、图是关系线索还是实验分数、政策日期如何绑定、何时 partial、何时审批、memory 和 PostgreSQL 重启行为差别。

亲自按启动说明跑一次，核对实际 C 盘源码导入和 E 盘环境；从新机器读者角度圈出必须改成本机路径的部分。产出一张自己的架构图和 200 字中文解释。不得把“LangGraph”一词当成已实现开放规划的证明。

## L5：现场演示并解释失败（90min）

按路线 5 脚本操作一笔当前增强调查，读主分数、模型/图版本、关系、政策原文与未知；填写演示 reviewer_id 和备注，拒绝建议，再刷新。解释为何未执行封卡。需要真实生成时必须通过本阶段受控预算，不能为练习反复点新调查。

再读一个明确标记的历史回放/部分证据案，说明它没有新推理、图不可用不是 0 或安全。练习 3～5 分钟讲述，遇到模型或数据库故障时说明原因和回退模式。按2026-10-18用户指令用实际页面截图替代录屏；代理截图/AppTest不代替本人演示，L5继续Pending。
