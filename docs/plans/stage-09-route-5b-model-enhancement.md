## 1. 总体目标与已确认决定

先给模型足够的信息和公平的比较条件，再判断图关系是否增加了价值；同时解决当前服务仅覆盖少数交易的问题。

| 决定 | 已确认内容 |
|---|---|
| 项目主线 | 仍面向 LLM/Agent 应用工程求职；图模型是调查工具的一部分 |
| 数据范围 | 固定 IEEE-CIS；本轮不换数据集 |
| GraphSAGE 角色 | 增量信号；证明融合或预先定义的关系子群收益后才接入决策 |
| 基础目标 | 增强版 XGBoost 的 ROC-AUC 最低目标 0.80；0.90 为探索目标 |
| 模型顺序 | 先补特征和强 XGBoost；当前同构 GraphSAGE 扩量/有限调参；无效再进入 v2；关系消融支持后才比较 HeteroGraphSAGE/R-GCN |
| 晋级门槛 | 相对增强版 XGBoost，融合平均 AP 绝对提升至少 0.005，Recall@Top1% 相对提升至少 5%；三时间折、三种子，至少两折正收益并报告不确定性 |
| 计算上限 | 最多 30 次新 GNN 训练、累计训练墙钟 12h、单次 60min；失败恢复计数 |
| 服务交付 | 完整验证/测试覆盖；无合格分数的关系邻居保留；新交易在线推理先完成小规模验证 |
| 退出机制 | 没有可信增量可以退出评分链路，保留确定性关系查询、实验性证据和负结果报告 |

0.80 是基础模型目标，不是 GraphSAGE 自动晋级线，也不能证明概率已校准或系统生产就绪。本轮不承诺达到 0.90，不通过换集合或选最好种子降低门槛。

## 4. 共同实验合同

### 4.1 时间划分与标签边界

1. 保留旧原始 train/validation/test 边界与哈希。新滚动实验从旧 train+validation 时段中预先冻结三组窗口；旧 test 不参与候选搜索。
2. 每组窗口包含更早训练期、随后内层调参/早停期、最后外层确认期。超参、早停和融合权重只用内层；三个外层结果在最终候选冻结后才统一查看，不能据其结果继续搜索。

路线0已具体冻结：development 501,959笔；三个训练期250,979/326,273/401,567笔，各内层早停25,098、校准25,098、外层50,196。候选搜索只用fold-1，之后按冻结规则做三折确认；后续折可使用此前已发生标签训练，不用外层成绩再改配置。详见[机器合同说明](../data/stage-09-model-enhancement-contract.md)和[路线0报告](../../reports/stage-09-route-5b-0-preflight.md)。
3. 每折 XGBoost、MLP、GNN 使用同目标集合和各自登记的相同训练截止。预处理只在该折训练期拟合。既有全训练期模型不用于更早折的公平基线。
4. 目标上下文只允许时间严格小于目标的无标签事件。同时间视为同时；历史节点特征按历史节点自己的时间生成。构图、邻居采样和特征不得读取标签。
5. 本数据的历史测试已被观察。最终候选冻结后至多一批历史 test 复核，报告为描述性复核；不称全新盲测，也不依据 test 更换候选或融合权重。
6. 外层访问约束降低本轮选型偏差，但不能恢复数据从未观察过的属性。相关交易、少量时间折和多次内层搜索的限制写入报告。

### 4.2 指标与门槛的准确口径

- AP 固定为 `sklearn.metrics.average_precision_score`；同时报告 ROC-AUC、正例率、Precision/Recall@Top1%/5%。不能把 AP 与梯形积分 AUPRC 混写，不能把 ROC-AUC 当准确率。
- 每折比较同 ID 的预测；先对 GNN 三种子求每折均值，再等权汇总三个时间折。各折/各种子/最差折完整列出，不能只选最好折。
- 增强 XGBoost 的最低基础目标是三折确认 ROC-AUC 均值 ≥0.80；0.90 为探索目标。每折数值与最差折必须披露，不表示每折都已达到0.80。
- `ΔAP = mean(AP_fusion - AP_enhanced_xgboost)`，全局晋级要求 ΔAP ≥0.005。
- Recall@Top1% 为按分数排序取 `ceil(0.01*N)` 笔的欺诈召回；并列时按冻结的交易ID规则处理。相对提升按每折 `(R_fusion-R_baseline)/R_baseline` 后等权汇总，要求 ≥5%。基线为0的折不得做相对除法，预先登记为不可按本条晋级并单列绝对差。
- 至少两个时间折 AP 正增益，最终候选共3折×3种子。报告配对差、种子波动及按时间块/相关交易处理的不确定性；无法支持稳定收益时不宣称稳定晋级。
- 只用受控、可复现的简单融合，不将训练内预测训练融合器；融合拟合用时间 OOF/内层预测，确认期和历史test仅推理。ROC-AUC作为辅助指标，必须披露融合变化，不能以一个指标掩盖另一个指标的明显退化。
- 增强基线未达到0.80时，不能仅凭相对该弱基线的提升通过GNN全局晋级；基础质量记未达标，图结果继续作为实验观察。达到0.80后仍须满足全部增量与稳定性条件。
- 关系子群需在查看输出前冻结定义、最小支持量、正例数、比较方法和用途；子群成员只由当时可见特征决定。小样本或事后挑选群体不晋级。子群收益只支持该群体辅助用途，不称全局通过。

### 4.3 预算、资源与版本

- 30次是所有新 IEEE-CIS GNN fit 的总上限，包括规模实验、消融、候选、种子、时间折和失败恢复；每个种子/折的独立训练算一次。小型机制fixture另记，不算真实质量证据。
- 分配：规模3次、有限参数6次、条件增强最多9次、最终确认预留9次、明确失败恢复3次，合计30次。完全相同的合法冻结运行可复用，记录绑定，不能用旧不同时段结果补三折。
- 每次60min、全部GNN训练12h；停止/失败耗时计入，不退款。不把预处理和缓存时间隐藏在训练数字里，另记完整实验耗时。
- 表格训练也有限：最多12次XGBoost fit、3次无图MLP fit；不能因GNN有预算便无限搜索表格基线。单次表格训练同样限60min并记录耗时；这些不是新增GNN额度。
- 资源门禁沿用旧线作为最低参考，启动时重测 RAM/GPU/C/D/E 可用量，按实际数据峰值提高所需余量。RTX2060 6GB、约16GB RAM是历史设备记录，不是本轮资源实测。
- 当前编辑工作树在C盘；大实验必须先在路线0确定E盘执行根、源码快照与产物根。uv缓存、Python、虚拟环境和TEMP仍在所选仓库内。大数据/缓存/权重不复制到C盘工作树，不改全局环境或迁移系统应用。
- 新预算与旧13次/6h训练账本分开，旧权重、哈希、测试和失败记录不覆盖。旧Stage09生成预算不增加；本轮模型/HTTP回放优先不调用LLM，新增真实生成如需要，先另行登记已有剩余额度。
- 原生CUDA训练、Ollama推理、Docker构建顺序执行。失去资源余量就暂停，不能自动关闭用户应用、删除卷或降低数据正确性标准。

### 路线 1：原始特征与时间正确管线

**实现目标。** 从compact数据扩展到有来源、可解释边界的宽表输入，保持旧调查接口兼容。

**步骤。**

1. 盘点 card/addr/email/device、dist、C/D/M/V/id 列及缺失率、类型、重复/常量；明确“原CSV存在但未进入模型”的字段。
2. 创建版本化侧表/特征schema，按TransactionID一对一对齐。重复、丢行、标签混入、异常类型显式失败；不静默填补未知身份。
3. 匿名原始列记录 `source_as_received` 和生成时点假设；未知生成时点不宣传为已经证明严格因果。先使用来源与可用性足够明确的字段，未知字段做独立敏感性分组。
4. 数值填补、类别词表、缺失标记与特征筛选只在每折训练期拟合。不做标签编码。自建频次/金额/时间统计严格使用更早事件。
5. 避免完整宽表反复复制；使用已有DuckDB/Parquet/分块方式。记录行数、schema、SHA-256和内存峰值。
6. 小fixture验证等时/未来事件不改历史特征、train-only预处理、侧表错配、缺失/未知类别和禁用列；旧canonical与调查工具继续可用。

**学习任务。** 完成LB1：追踪一列从CSV到模型，区分缺失值、0、未知类别与不可用字段；解释时间切分为何不自动保证全管线无泄漏。

**交付/验收。** 字段用途表、特征manifest、时间边界测试、内存记录、路线1报告；标签列与未来统计不可进入输入。

**2026-10-09工程证据。** [路线1报告](../../reports/stage-09-route-5b-1-features.md)与[字段合同](../data/stage-09-model-enhancement-features.md)：全部590,540笔、431原始字段+24派生、侧表约109MiB；core38→63列、source_as_received454→871列，两套各完整转换250,979个训练ID。独立历史180项复算通过；75 passed/1旧符号链接skipped；196秒、峰值工作集1.72GiB、可用RAM最低4.74GiB。493输入绑定、共享fit/外层/test0；匿名时点限制与fold-2/3后续拟合保留。模型效果未评估，路线2未开始，LB1本人待完成。

### 路线 2：增强 XGBoost 与公平基线

**实现目标。** 建立能充分利用数据的参照，避免GNN只击败简化模型。

**步骤。**

1. 原14字段、增强宽表XGBoost分开报告；规模/截止/目标与特征输入明确，原Stage02 champion只作为历史参照。
2. 冻结最多三个候选配置，内层时间窗口早停/选型；先确认GPU或CPU运行路径、依赖版本和数据预处理一致性。
3. 在fold-1保留当前28维根输入的XGBoost/无图MLP对照；三次XGB control分别用于旧14字段/core/28维输入诊断，另一次MLP control用于28维，后两折MLP额度等最终冻结。后续GNN改输入时重新建立对应无图对照，不借不同输入证明图收益。训练安排见[冻结附录](../data/stage-09-enhanced-baselines.md)。
4. 选择并冻结增强基线版本；最终外层三折得分在路线5统一确认。内层达到0.80只能算开发结果，不能提前标最终质量通过。
5. 保存权重/encoder/特征manifest及预测重载一致性；失败、预算耗尽和未达到目标分别报告。

**学习任务。** 完成LB2：理解早停、PR与ROC的区别、为何全量模型与50k模型可能各指标不同。
