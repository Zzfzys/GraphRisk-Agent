# Stage 03 实施路线：确定性调查工具与无 LLM 工作流

> 编写日期：2026-09-22  
> 计划投入：Week 4，约 20～24 小时  
> 当前状态：路线 0～2 已完成；路线 3～6 尚未实现

## 最终目标与边界

输入一个已有的 `transaction_id`，系统在不调用 LLM 的前提下，按固定顺序读取交易事实、严格历史特征、表格模型风险分数和历史关联证据，输出有来源、有限制说明的结构化调查报告。每个工具可以独立调用和测试；失败时说明具体环节，不把缺失证据编成结论。

Stage 01 已提供 DuckDB/Parquet、canonical transaction 和严格历史窗口；Stage 02 已提供 `RiskPredictor`、两套 champion 和 FastAPI。默认演示采用 IEEE-CIS 与其 XGBoost champion，合成数据用于确定性测试。运行配置必须显式绑定同一数据源的交易、特征和模型，不能混用。

这一阶段只做只读、确定性调查。LLM、RAG、LangGraph、GraphSAGE、Neo4j、自动封禁和审批界面均不在本阶段实现。IEEE-CIS 的 `TransactionDT` 使用人工时间锚点，只能解释相对先后和间隔；`identity_key` 等实体也不能称为真实用户身份。

```text
transaction_id
  → 参数校验与数据源绑定
  → get_transaction
  → get_transaction_features
  → get_risk_score
  → get_related_entities
  → find_risky_neighbors（明确返回 unavailable）
  → 汇总证据、限制和审计事件
  → 结构化基础调查报告
```

`get_related_entities` 在 Stage 03 只查询 Parquet 中能够直接验证的历史共享实体；它不是 GNN 结论。`find_risky_neighbors` 此时只固定接口并返回 `unavailable`，Stage 04 再接入真正的图查询与 GraphSAGE，不伪造风险邻居。

本周建议总投入 22～23 小时，其中约 4.5 小时用于带着当前交付目标学习；其余时间用于实现、测试、代码阅读、演示和记录。每条路线学完后写 3～5 句话解释一个实际输出，作为自己的学习笔记。

## 路线 0：确认调查语义与数据源（约 2 小时）

**进度：已完成。** 路径、字段、真实交易抽查和学习解释见 [路线 0 验证记录](../../reports/stage-03-route-0-semantics.md)。

**实现目标：**核对 IEEE-CIS 的交易、特征与 champion 路径，制定字段允许清单和禁止清单。明确记录数据源与产物路径/版本的绑定关系；现有特征 Parquet 本身没有 `dataset_source` 字段，不能仅凭列名猜测来源。`is_fraud` 仅为离线评估标签，不得出现在调查工具和报告中。明确原始事实、历史统计、模型分数和推断性结论的区别。

**学习任务：**阅读 `docs/data/data-dictionary.md`、`docs/data/ieee-cis-adapter.md`、`src/graphrisk/features/transaction_features.py` 和 `src/graphrisk/serving/predictor.py`。能独立解释 `TransactionDT`、人工锚点、同时间交易、`identity_key` 和“模型分数尚未校准”的含义。

**交付与门禁：**在阶段文档记录数据源、可展示字段与禁用字段；人工核对至少一笔真实交易与模型版本。若模型和特征来源不同，先停下纠正配置。

## 路线 1：统一工具契约与错误分类（约 3 小时）

**进度：已完成。** 五个请求/结果 schema、统一外壳、错误码与契约测试见 [路线 1 验证记录](../../reports/stage-03-route-1-contracts.md)。此处只固定接口；`find_risky_neighbors` 的成功 schema 为 Stage 04 预留，不代表 Stage 03 已有图查询。

**实现目标：**为五个工具设计 Pydantic 输入、输出和统一结果外壳。结果至少含工具名、交易 ID、数据源、状态、证据引用和可机器读取的错误码。区分 `ok`、`not_found`、`invalid_input`、`unavailable`、`dependency_error`；不把异常堆栈或磁盘路径直接当业务输出。接口能在后续被 LangGraph 包装，但本阶段不依赖 LangGraph。

**学习任务：**学习 Pydantic 字段约束、结构化输出、schema 序列化和异常分类。对照现有 `RiskPredictionRequest`，解释为什么输入校验在查询前，以及“无此交易”和“模型产物缺失”为何不同。

**交付与门禁：**每个工具有输入/输出示例和小型契约测试；空白或过长 ID、无记录、产物不可用均返回稳定结构。

## 路线 2：交易与历史特征工具（约 4 小时）

**进度：已完成。** 只读查询、真实 IEEE-CIS 抽查、时间/缺失值 fixture 和错误分支见 [路线 2 验证记录](../../reports/stage-03-route-2-transaction-tools.md)。

**实现目标：**实现 `get_transaction` 和 `get_transaction_features`。使用只读 DuckDB/Parquet repository，以参数绑定查询唯一交易；返回金额、产品、建模实体、相对时间和已有历史窗口特征。保留缺失历史统计的 `null`，不伪造零值。交易输出采用字段允许清单，排除 `is_fraud`、未经确认的真实身份和无关匿名宽表字段。

**学习任务：**学习 DuckDB 参数化查询、Parquet 列投影、唯一性断言与 `NULL` 语义。手算一个含同时间交易的小样本，解释当前及同时交易为何不进入其历史特征。

**交付与门禁：**小型确定性 fixture 和真实 IEEE-CIS 交易均可查询；不存在的 ID 为 `not_found`，重复 ID 或缺失文件不会被吞掉；输出没有标签泄漏，并能指明来源交易或产物。

## 路线 3：风险模型工具（约 3 小时）

**实现目标：**实现 `get_risk_score`，直接复用 Stage 02 `RiskPredictor`，不复制预处理或重新训练。返回分数、等级、模型名与版本、数据来源和“概率未校准”的限制。启动时通过显式数据源配置/产物清单与模型 metadata 检查同源，不能从同形 schema 推断来源；区分模型缺失、交易缺失和推理失败。此工具只读，不触发处置。

**学习任务：**学习模型 artifact、metadata、版本和推理边界。解释为何 `0.8` 不能写成“80% 确定欺诈”，以及为何不能根据测试集表现反向选择 champion。

**交付与门禁：**同一交易的分数与现有 `/risk/predict` 一致；交叉配置合成模型和 IEEE-CIS 特征会被拒绝；缺失模型产生结构化 `dependency_error`。

## 路线 4：本地关系证据与图工具占位（约 4 小时）

**实现目标：**实现 `get_related_entities`：取目标交易的 card、device、email、address，只查询目标交易**严格之前**共享实体的交易，返回实体类型与 ID、关联交易 ID、相对时间差和匹配依据。默认排除交易唯一的 `unknown-*` 占位实体。结果稳定排序，限制返回行数并提供总数；同一 `TransactionDT` 的交易不能称为历史关联。`find_risky_neighbors` 只返回结构化 `unavailable`，指向 Stage 04。

**学习任务：**学习一跳关系、共享实体、时间截断和缺失值伪连接。手绘 3～5 笔交易的小图，区分“历史交易共享 card”和“邻居被模型判高风险”这两种完全不同的主张。

**交付与门禁：**测试覆盖四类实体、重复命中去重、`unknown-*` 排除、同时间隔离、未来隔离、排序与上限。没有历史关系时返回空列表和 `ok`，不虚构邻居；占位工具有独立测试。

## 路线 5：确定性工作流、报告和审计（约 4 小时）

**实现目标：**按固定顺序调用工具，生成不含 LLM 文案的结构化报告：交易概览、历史特征、表格风险分数、关系证据、不可用能力、错误和限制。每条可核验结论引用产生它的工具与交易/实体标识。审计事件记录 `investigation_id`、调用顺序、工具、起止时间、状态与耗时；不记录密钥、完整原始宽表或无必要的敏感值。相同数据与模型版本下，相同输入产生相同调查内容；trace ID 与执行时间单独属于审计元数据。

**学习任务：**学习有限状态工作流、幂等性、证据链和失败恢复。画出“交易不存在”“模型不可用”“无历史关系”三条分支，解释哪些错误使流程停止，哪些允许带明确缺口继续。

**交付与门禁：**一个命令行演示入口和固定 fixture 报告；测试成功、部分失败、无效参数和重复调用。报告不能将模型分数、历史关联或 `identity_key` 表述为欺诈定论或真实身份。

## 路线 6：端到端验收与学习复盘（约 2～3 小时）

**实现目标：**运行全量测试、独立工具测试与真实 IEEE-CIS 调查演示；检查报告中没有未来交易或标签。记录命令、耗时、失败案例和实际输出，更新 Stage 03 与 README。全部门禁有证据后才改成 `Done`。

**学习任务：**亲自解释报告每个字段的来源，并回答：删除模型文件、输入不存在 ID、增加未来交易时输出分别应如何变化。把尚不理解的 SQL、工具设计或统计概念记入复盘。

**交付与门禁：**自动化测试、可重复演示命令、至少一份最小化的 IEEE-CIS 调查样例、审计样例和阶段验证报告。原始 Kaggle CSV 与完整导出数据不提交 Git。

## 建议的一周节奏

| 时段 | 路线 | 可见进度 |

| 第 1 天 | 0、1 | 数据语义确认、schema 与错误码草案 |
| 第 2 天 | 2 | 交易和特征查询、边界测试 |
| 第 3 天 | 3、4 前半 | 风险工具、实体关系 SQL |
| 第 4 天 | 4 后半、5 | 时间门禁、工作流与报告 |

每天至少留 30～60 分钟读当天涉及的代码并解释一个实际输出。时间紧张时先保证交易、特征、风险分数、结构化错误和基础报告，再压缩关系证据的展示数量；不能通过放宽时间门禁、使用 `is_fraud` 或伪造图结果赶进度。

## 全阶段验收清单

- [ ] 每个工具可以独立调用，输入与输出通过 schema 验证；
- [ ] `is_fraud` 不进入工具输出、调查报告或关系证据；
- [ ] 历史关系严格早于目标交易，同时间和未来交易不能成为历史证据；
- [ ] `unknown-*` 占位值不会形成虚假共享实体；
- [ ] 模型与数据源一致，风险分数与既有 API 一致；
- [ ] `not_found`、`invalid_input`、`unavailable`、`dependency_error` 可以区分；
- [ ] 无 LLM 工作流完成一次 IEEE-CIS 交易调查并输出可引用证据；
- [ ] 每次工具调用都有可追踪审计事件；
- [ ] 自动化测试、真实样例、文档和复盘齐全，原始受限数据未进入 Git。

## 风险与下一阶段输入

- **高基数与延迟：**Stage 02 的 IEEE-CIS 单请求约 0.8 秒。本阶段先保证正确性并分别测量查询与推理耗时；有证据后再优化缓存或批量查询，不缩小数据来掩盖问题。
- **数据库未接入：**使用只读 DuckDB/Parquet repository；PostgreSQL 和 Neo4j 不是本阶段门禁。
- **图能力未完成：**风险邻居明确返回 `unavailable`，Stage 04 在相同契约下替换实现。
- **历史标签可见性未知：**不将 `is_fraud` 当作调查时已知事实，也不按标签挑选“高风险邻居”。
- **时间语义：**IEEE-CIS 人工锚点不能用于真实日期叙述；关系查询按相对先后判断。
- **Stage 04/05 输入：**稳定的工具 schema、关系查询接口、可引用证据格式和失败/审计记录。
