# Stage 07：Agent 强化与正式基础设施

> 状态：Planned  
> 计划时间：Week 9～10  
> 前置阶段：Stage 06

## 阶段目标

基于 MVP 的真实失败案例提高 Agent 可靠性，并逐步替换临时基础设施实现。

## 实现任务

- [ ] 对评估失败进行分类和优先级排序；
- [ ] 扩充工具选择、参数、引用和恢复案例；
- [ ] 优化工具描述、状态流转和终止策略；
- [ ] 正式接入 PostgreSQL 与 pgvector；
- [ ] 根据展示价值接入 Neo4j；
- [ ] 增加 checkpoint 和调查会话恢复；
- [ ] 建立请求 ID、工具轨迹和结构化审计日志；
- [ ] 对比基础设施迁移前后的行为一致性。

## 交付物

- Agent evaluation report v2；
- 失败分类与修复记录；
- PostgreSQL/pgvector 集成；
- 可选 Neo4j 图查询；
- 会话恢复与审计日志。

## 验收标准

- [ ] 每个高频失败类型都有测试或明确接受理由；
- [ ] 基础设施替换不改变工具对外契约；
- [ ] 会话能够从保存状态恢复；
- [ ] 调查链路可通过 request ID 追踪；
- [ ] 评估报告包含与 MVP 的对比。

## 风险与降级方案

- Neo4j 运维成本高：保留本地图查询并把 Neo4j 移为扩展；
- pgvector 迁移阻塞：继续使用 Retriever 接口的本地实现；
- 修复造成指标互相牺牲：记录权衡并保留版本化评估结果。
