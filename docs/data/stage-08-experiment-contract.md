北京接口模板为 `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/chat/completions`；WorkspaceId/最终 endpoint 必须来自账号控制台，不能把模板直接发送。密钥环境名 `DASHSCOPE_API_KEY`。路线 3 首次真实请求前核对区域、模型权限、endpoint 和当时价格；不要求用户在聊天中提供密钥。[官方兼容接口](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)。

采用 JSON Object，并在本地做 Pydantic/schema 和证据核验。JSON Object 只约束 JSON 形式，不能保证字段和引用正确；不把它宣传为该快照原生 strict JSON Schema。提示词明确要求 JSON。[结构化输出说明](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

## 模型对照与 GraphRAG 分开评分

本路线冻结**设计、分组和门槛**；还未编写/冻结具体题目。题目及黄金证据分别在路线 3/4 调试之前冻结哈希；开发集单独存放，不对冻结题调参、改预期。

| 数据集 | 分组与数量 | 用途 |
|---|---|---|
| 旧 Stage06 50 案 | 原哈希保留，fake/系统回归 | 证明系统机制，不能排名模型 |
| 旧 Stage07 15 案 | 原哈希保留，真数据库/受控故障 | 恢复、持久化、证据安全 |
| provider 20 案 | 归纳 6；JSON/字段 4；信息不足 4；错误/过期引用 4；注入 2 | 同输入真实模型对照 |
| GraphRAG 30 案 | 直答 8；两跳 8；版本/冲突 6；无答案 4；注入 4 | 三检索模式消融 |

provider 使用完全相同的提示词、上下文、schema、输出模式 JSON Object、输出限额、时间和评分器。保留现有生产基线的 schema 模式；新评估入口单独使用共同 JSON 模式，并记录 API 实现差异。共同输入必须满足每个模型自己的输入上限，不能单边截断。首答与重试后成功分列；错误、超时保留在分母。记录 JSON/schema 有效率、证据/引用错误、拒答、注入违规、冷/热墙钟 P50/P95、usage 与费用；20 案不作统计显著性或生产能力宣称。

GraphRAG 22 个可回答案（含 6 个有明确期望的版本/冲突案）至少 18 正确，其中两跳至少 6/8；无答案 4/4 拒答；注入 4/4 不执行文档指令；伪造引用/边为 0。最多两跳；每条边必须绑定原文 chunk 和有效期。引用正确与答案事实正确分别评分，全部案例保留。模板之外的传输故障用 fake 测试，不能充当真实模型正确率。
