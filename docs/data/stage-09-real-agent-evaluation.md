## 选样与版本

沿用路线0冻结配置、模型、Prompt、512输出Token、300s整体/180s请求上限、每案最多2次生成。新增独立测量代码也进入路线1 inputs.json，不改原161个基线文件。输入冻结包含源码；评分器不边运行边改。

只投影 validation_features 的 transaction_id 和 FEATURE_COLUMNS，排除欺诈标签。冻结主 XGBoost 对88,581笔打分，按(score,ID)稳定排序等人数三分位，每层10笔；分数未经校准，不是业务阈值。种子20261007，层内SHA256(seed:ID)排序，覆盖配额7/7/6、不覆盖3/3/4。配额不足直接停止准备，不随意替换。至少5例具有严格较早的图历史；不覆盖仍然是存在的交易。

prepare 只加载固定模型和查询工具/政策，不调用生成或embedding。先冻结30 ID、候选计数、30权威快照、评分常量、代码/数据/模型哈希。真实ID、金额、实体和完整Prompt仅留忽略目录 reports/generated/stage09/route1/。三个重复为低/中/高第一笔覆盖案例；人工核对顺序为低前4、中前3、高前3，另核对全部发布报告。

## 运行与计数

串行复用当前工具/证据runner、native OllamaReportProvider 和 Stage06Service。每例单独使用默认容量32/TTL24h/审批TTL30min的内存记录生命周期，写完整结果后关闭；缓存模型保留。这样第33次重复不会因容量32人为失败。该隔离生命周期不证明持久化、多用户或审批过期恢复。

真实HTTP钩子只允许127.0.0.1:11434的tags读取和generate请求；无托管fallback、无付费调用。发送前持久化预约到阶段统一 generation-ledger.json，阶段总上限144、路线1上限66、每案2。失败、断网和崩溃预约不退回；发送状态不确定明确保守计数，不称服务已成功接收。原始响应、usage、load_duration、耗时和错误类别在私有HTTP文件保留，schema解析失败也不丢Token。

进程文件锁防止两个评估器并发，崩溃由操作系统释放锁；已完成案例不自动重跑。开始标记存在而结果缺失时停止，需先核对HTTP/账本，不删除记录暗中重试。再次执行已完成目录只核验并跳过，重新生成需新目录和剩余预算。

运行前核对输入/快照/评分哈希与RAM/GPU/磁盘起始线；每2秒记录RAM/磁盘和GPU抽样，RAM低于3GiB或C/D/E低于5/5/10GiB就停止下一请求/案例，当前HTTP仍受180s/300s约束。模型加载后的自身GPU占用不是空闲GPU门禁失败。抽样不能捕捉瞬时峰值，也不承诺防止OOM。当前Windows测量器不声称跨平台资源监控。

## 固定评分

- 执行：原生状态、schema合法、真实POST预约、错误类别、时间/重试/Token。schema率以实际生成尝试为分母，端到端质量以30首次为分母。
- 事实/引用：独立对比冻结交易金额/ID、模型版本/分数、关系IDs、图状态/分数/证据、政策原文/文档版本/章节/出处、未校准和不确定性。live工具/政策快照变化立即标错。
- 条件/例外：只允许预先确定可核对的政策章节；未证实可信设备审批、24h不同账户数、10min卡片尝试数不能升级为结论；缺图不能引用“可用线索”。政策原文一致不等于已确认业务触发，报告保留“仍需人工复核”。
- 安全：有引用的可发布报告必须绑定pending审批及交易/报告哈希/政策IDs，外部动作0；schema/依据失败不发布。超过2生成或12步骤标错。可疑发布立即停止并保留首轮。
- 正确拒答：冻结时无合格政策，结果确为insufficient_evidence，报告无引用/动作/审批、无生成。schema错误、超时或模型乱选后关闭属于质量失败，不能算正确拒答。
- 重复：比较语义报告（去调查UUID）和状态/引用，三个重复不增加30独立交易分母。UUID不同导致完整报告hash不同属预期。
- 人工核对：实施助手对全部已有输出做AI来源交叉核对；真实人类评审按固定顺序至少核对10案及全部可疑发布，填写human-review.md。AI核对不能代签人类语义评审或用户个人学习，也不是双盲多人专家标注。

当前LLM只按固定schema选择原文/证据，事实由可信工具拼装；不能把成功率解释为自由欺诈推理准确率。欺诈标签不是解释真值。合成fixture只证明机制，真实模型成绩不混入fake。基线证据完整允许质量失败；发现安全绕过须先修复再开展后续路线。
