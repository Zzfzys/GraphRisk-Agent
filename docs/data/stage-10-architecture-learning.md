# L4：能把系统讲清楚（90分钟）

材料就绪，本人状态Pending。每天30分钟，依次读[中文首页](../../README.zh-CN.md)、[架构](../architecture/stage-10-system.md)与[本机启动](stage-10-author-workspace.md)。

## 第一天：从读者问题出发（30分钟）

不用历史聊天，用五分钟回答“做什么、输入什么、输出什么、目前成绩怎样”。找出6/10、GNN不晋级、GraphRAG模拟集和生产缺口的出处。区分公共50案机制CLI与真实模型网页；解释为什么下载CSV后还不能直接调查。

产出200字自己的项目介绍，以及三种运行方式各需要哪些输入。不要把模拟案例数量写成真实模型成功笔数。

## 第二天：沿一次请求读源码（30分钟）

从streamlit_app.py的提交进入api/investigation.py，再到服务、ReliableRunner、证据图、QualityReportWorkflow和审批图。画出自己的箭头：交易/历史、XGB、关系/实验图、政策、模型判断、核验、报告、审批。

回答：draft_stub是否真的调用LLM？哪个阶段核验模型的未知项？为什么工具顺序不是模型自由决定？为什么引文真实仍须判断政策适用？

产出自己的架构图，给每个箭头写一句话；对照源码地图定位至少三个符号。

## 第三天：解释启动与恢复（30分钟）

先读脚本不新建调查，预测8000、8501、8502分别是谁。看health与ready区别，解释“API没开”“依赖缺失”“报告生成被拒绝”的不同含义。如果已有服务可只读检查；启动练习按本机说明，在个人操作记录中写清自己实际执行了哪些步骤。

比较memory重启丢失、postgres同run恢复和历史报告回放；解释为什么GRAPHRISK_HISTORY_REPLAY标识不会把真实服务变成回放。画一次审批重试/冲突的时序，指出report_sha256/session_id/TTL的作用，以及reviewer_id未认证的边界。

产出自己的恢复流程和一项故障判断。真实生成预算仅剩2，页面操作不自动受实验次数账本保护；个人练习使用已存报告/回放，不为练习反复调用模型。本路线材料和CLI检查不代替你本人启动或口述，实际演示/录像在路线5另记。
