## 先写下预测：什么证据能回答你的问题

“GraphSAGE是完全体吗”分为实现是否正确、历史是否真的传到根、采样/特征是否适合业务、优化与泛化是否充分。路线2核验了前两项；路线3提供了公平根特征对照；本路线用真实重训、有限参数搜索和种子波动判断后两项。有限搜索仍不能证明全局最优或生产适用。

在读实验结果前，预测五种图的排序并解释原因：

| 实验 | 固定不变 | 改变 |
|---|---|---|
| 完整图cap5 | 50k/10k、根特征、节点/时间规则、seed20260921 | 本轮统一50epoch/patience10重训 |
| 去边 | 节点/根/特征/目标/预算 | 所有消息边移除；SAGE自分支保留 |
| 合法类型重连 | 节点、根边、节点度、类型次数、历史截止 | 每种实体类型的历史边端点固定种子置换 |
| 去历史数值 | 根完整、拓扑、产品/类型 | 历史交易的9数值和9缺失指示置0 |
| cap10 | 同目标/encoder/参数 | 每根实体更早交易上限5→10 |

去边不是“将旧权重删边后预测”。每项都重新从固定种子初始化训练。旧权重删边只能说明敏感性，不能替代重训消融。去边有自变换；虽然形式接近根MLP，初始化、无效参数和训练路径也可能不同，不能直接把两份checkpoint等同。

重连仅发生在同一目标的合法历史内，每类实体独立置换历史边的实体端点；根边固定，双向边成对生成，节点/度数/实体类型计数不变。同一历史交易每类最多一条边，不能制造重复边。完全共享同一个实体的组无法改变，必须报告实际改变率，不称“所有图被扰乱”。这只检验已有历史集合内的关系分配，未改变历史交易的入选集合，无法代表任意负采样。

## 30分钟一：核对缓存与原实现

为了减少内存并避免每个epoch重复Python编码，本路线按时间顺序读取原无标签Parquet，保留每种实体最多10笔历史。整个同时间组先构图再更新，保证同时间不可见。时间相同的旧历史组取ID升序前若干笔，与原索引一致；ID仅作确定性同时间选择，不是时间先后。

完整图、重连图写到E盘二进制缓存；训练按目标取图、拼接节点/边，并偏移根索引，PyG每张图仍独立。去边/去历史数值复用完整缓存，在取batch时进行明确变换。缓存不存标签；标签来自路线3已冻结的train/validation数组。

先读：
- `src/graphrisk/graph/stage09_packed.py`：stream_graphs、project_variant、PackedGraphs.batch；
- `src/graphrisk/graph/stage09_budget.py`：reserve、guard、seal_test；
- `src/graphrisk/graph/stage09_diagnosis.py`：fit_gnn、pick_winner、evaluate_decision。

```powershell

uv run --offline pytest tests/unit/test_stage09_diagnosis.py -q
```

亲手追踪一个“同时间旧事件多于10笔”的fixture，比较缓存与TemporalEntityIndex的node_keys/特征/边/根，说明为什么简单保留最后10个ID会取错。同一测试还检验原生Batch与缓存Batch评分完全一致；真实全10k旧checkpoint复现是另一个门禁，小fixture不能替代它。

## 30分钟二：读曲线与有限参数搜索

最多50epoch、patience10；验证AP最高的权重单独clone并保存，结束后恢复。train loss降低但validation AP不上升时，继续增加epoch不自动有效。项目PR-AUC实际是average_precision_score（AP），与ROC-AUC、Top1%/5%Precision/Recall一起读。

固定六个组合：

| lr | dropout | hidden |
|---:|---:|---:|
| 0.001 | 0.2 | 64 |
| 0.0005 | 0.2 | 64 |
| 0.001 | 0.4 | 64 |
| 0.0005 | 0.4 | 64 |
| 0.001 | 0.2 | 128 |
| 0.0005 | 0.2 | 128 |

第一组已等于完整图基线，复用相同运行；五项基础/消融+另外五个搜索+最佳方案两确认种子，实际计划12次唯一训练。13次是上限，不能为了凑满再加一个看完结果才发明的候选。MLP/XGBoost路线3各一次额度已用完，本路线不重训。

训练前注册CUDA设备、CPU线程4、batch256、seed20260921；确认种子20260928/20261007。每次最多1h，准备/图构建/复现与训练验证共用6h墙钟账本，失败消耗额度、不退还。GPU运行的固定种子不保证跨平台/不同内核位级相同，因此质量用三种子实测，不承诺CUDA绝对确定性。

先按最高验证AP挑可部署候选（完整图六配置和cap10；去边/重连/去历史数值仅诊断），并在分数相同情况下保留预注册顺序较早者。不要看测试来选lr、采样或种子。

从报告曲线抄最佳/停止epoch、train loss、AP/ROC；分别提出过拟合、欠拟合、时间迁移三种解释，并列出支持/反驳证据。早5000与晚5000的正例率不同，比较AP时必须一起写正例数。

## 30分钟三：自己作一次模型决策

三种子同10k验证目标，按预注册规则：平均AP至少超过两种业务XGBoost中较高者0.005，且每个种子均超过该业务参照，才建议晋级GNN候选。否则建议已有Stage02 XGBoost评分+真实图证据+明确的实验性GNN分数。阈值是本项目工程决策规则，不是统计显著性或行业标准。

质量报告列每种子AP/ROC/TopK、均值/波动、同目标配对差异和早晚分组。相关交易、反复使用验证集和三个种子限制解释，不把标准差当置信区间。当前0.5阈值以及sigmoid均未校准。

选择结果先保存带SHA的decision.json，再封存最多一次历史测试复核。历史测试不是全新盲测，复核仅固定10k目标、三个已选GNN种子和旧模型；复核后预算拒绝新增候选训练，不据测试改选型。真实复核失败也消耗一次额度，不能假装未发生。

`diagnose_stage09_graphsage.py prepare/run/final-review` 是实际执行入口，执行记录放私有route4目录。不要把run/final-review当普通复现命令重复执行；先使用报告里的只读核验入口，避免重读测试或新增训练。原评分服务的切换和30笔Agent重放属于路线5，本路线仅保存模型决策与版本化证据。

最后用自己的话回答：实现有没有错误、历史消息是否有效、哪些特征/关系限制了结果、调参是否稳定、默认评分模型选谁、尚不能证明什么。本人学习记录不由自动化或测试代签。


## 本轮资源与复现边界

缓存仅保留后续目标仍会查询的实体历史，并在该实体最后一个目标查询后释放。预读的只有目标时间和实体键，用于减少内存中的索引；历史节点内容和选入关系仍只来自严格更早事件。fixture逐图哈希和全10k旧checkpoint复现共同核验结果一致。

GPU信息在阶段边界查询，RAM和磁盘每2秒检查。nvidia-smi超时最多尝试三次，必须取得新的成功测量；其他测量失败、真实资源越线仍停止。失败构建耗时仍记账，完整缓存核验后复用，不重新制造一份缓存。
